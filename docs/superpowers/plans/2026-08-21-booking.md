# Booking Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A company gets one bookable calendar; a stranger books a slot from a public page or embed; the company is alerted like a lead; the booker is confirmed, can cancel, and is reminded 24h before.

**Architecture:** One `calendars` row per account and a `bookings` table whose double-booking guarantee is a Postgres **exclusion constraint**, not an app check. A pure, timezone-correct slot engine feeds a public page at `/b/<publicId>` that mirrors `/f/<publicId>` (branding, spam gates, embed). Booking runs the M1c lead pipeline (contact dedupe → conversation → unread → branded alert) plus a confirmation email carrying a cancel link. One reminder email is driven by the platform's first Vercel cron.

**Tech Stack:** pnpm monorepo · Next.js App Router (`apps/web`) · `packages/db` (Supabase/PostgREST + SQL migrations) · vitest · Playwright · Resend · Vercel cron.

**Spec:** `docs/superpowers/specs/2026-08-21-booking-design.md` — read §2 (locked decisions), §3 (schema), §4 (slot engine), §7 (cron) before Task 1.

## Global Constraints

- **The CONTROLLER applies migration 0016, never an implementer.** One Supabase project, production reads it. Same protocol as 0015: write the file, report DONE_WITH_CONCERNS, stop.
- **Double-booking is enforced by the DB exclusion constraint.** The app's availability check is UX; the constraint is the guarantee. Never remove or weaken `bookings_no_overlap`.
- **All slot arithmetic runs in the ACCOUNT's timezone with `timeZone:` passed explicitly to every `Intl.DateTimeFormat`.** Node caches the process zone, so `process.env.TZ` in a test proves nothing — tests spy on the constructor and assert the pin.
- **The public submit path runs on `serviceDb()`** (an anonymous booker has no role), gated by `calendars.enabled`. Operator reads/writes run on `dbForRequest()` — calendar settings are client-editable business data (M4c precedent), enforced by RLS + column grants.
- **Reminder ordering is send-then-stamp** — the reverse of messaging's write-then-send, because `reminder_sent_at` is a dedupe marker: stamping before a failed send silences the reminder forever.
- **No internal roadmap labels in any copy string** (`messages.test.ts` enforces `/\bM\d[a-z]?\b/`). The milestone is called “Booking”, never “M2”.
- **Every absence assertion ships with a positive counterpart** locked to the same string/selector. Two vacuous guards were found in the last milestone alone.
- **Test commands:** `pnpm --filter <pkg> exec vitest run <pattern>`. The `test -- <name> --run` form does NOT filter — it runs the whole suite.
- **`emit` is `emit(db, accountId, type, actorId, payload, actorType = "user")`.** `createContact(db, accountId, input, actorId)` → `{ id, existing }` and dedupes internally. `ensureConversation(db, accountId, contactId, actorId)` → `{ id, created }`. `createMessage(db, accountId, {conversationId, channel, direction, subject?, body}, actorId)` → `{ id }`. All verified against source.
- **e2e reds are judged by WALL CLOCK** (cold 6–8 min flaky, warm ~2–3.5 min). Re-run, then the spec alone, before believing one.
- **Blueprints must never capture calendars** (spec §11). `buildBundle` enumerates its five tables explicitly, so no code change is needed — the constraint is: do not add `calendars` to that list. Cloning would copy `public_id` semantics that must stay globally unique.
- **Two columns are plan-level refinements the spec's §3 table omitted**, both forced by the spec's own email/anti-spam sections: `bookings.booker_timezone` (the reminder must speak the booker's local time — §7 — and the reminder fires ~24h after the browser is gone, so the zone must be stored) and `bookings.ip_hash` (the §5 rate limit needs something to count). Recorded here so nobody "fixes" the migration back to the table.

```sql
-- (as corrected by 0017 — policies scoped to authenticated, FKs restrict; see that migration's comments.)
-- Booking: one calendar per company, bookings whose no-overlap guarantee
-- lives HERE, not in application code.

-- btree_gist lets a gist exclusion constraint carry the uuid equality leg.
create extension if not exists btree_gist;

create table public.calendars (
  id uuid primary key default gen_random_uuid(),
  account_id uuid not null references public.accounts(id) on delete restrict,
  -- One calendar per company is SCHEMA, not convention (spec §2 decision 1).
  constraint calendars_one_per_account unique (account_id),
  public_id text not null unique,
  -- Nothing is bookable until someone turns it on.
  enabled boolean not null default false,
  slot_duration_minutes int not null default 60 check (slot_duration_minutes between 5 and 480),
  buffer_minutes int not null default 0 check (buffer_minutes between 0 and 240),
  min_notice_hours int not null default 12 check (min_notice_hours between 0 and 168),
  max_advance_days int not null default 30 check (max_advance_days between 1 and 365),
  -- Per-weekday intervals: {"mon":[["09:00","17:00"]], ...}. ONE set for the
  -- company — no per-member availability, deliberately (spec §2 decision 1).
  open_hours jsonb not null default '{}'::jsonb,
  -- Same semantics as forms.notify_emails: empty means the booking alert goes
  -- nowhere, and the settings panel warns inline.
  notify_emails text[] not null default '{}',
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create table public.bookings (
  id uuid primary key default gen_random_uuid(),
  account_id uuid not null references public.accounts(id) on delete restrict,
  calendar_id uuid not null references public.calendars(id) on delete restrict,
  -- Non-null: a booking cannot exist without its person (spec §6 step 2).
  contact_id uuid not null references public.contacts(id) on delete restrict,
  starts_at timestamptz not null,
  ends_at timestamptz not null,
  check (ends_at > starts_at),
  status text not null default 'booked'
    check (status in ('booked','cancelled','completed','no_show')),
  note text,
  -- The capability in the confirmation email. Opaque; knowing it IS the
  -- authorisation to cancel, exactly as knowing a form's public_id is the
  -- authorisation to submit.
  cancel_token text not null unique,
  -- The booker's IANA zone, captured from their browser at booking, so the
  -- confirmation and the reminder can speak their local time.
  booker_timezone text,
  -- Rate limiting: hashed submitter IP, same hashing as form submissions.
  ip_hash text,
  -- THE reminder dedupe marker. Null = not yet sent. Stamped AFTER a
  -- successful send, never before (spec §7 — send-then-stamp).
  reminder_sent_at timestamptz,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

-- Two racers for one slot resolve in the database: the loser gets this
-- constraint, surfaced as "that time was just taken." Only live bookings
-- bind — a cancelled booking frees its range.
alter table public.bookings add constraint bookings_no_overlap
  exclude using gist (
    calendar_id with =,
    tstzrange(starts_at, ends_at) with &&
  ) where (status = 'booked');

create index bookings_reminder_due
  on public.bookings (starts_at) where status = 'booked' and reminder_sent_at is null;
create index bookings_by_calendar on public.bookings (calendar_id, starts_at);

-- RLS: house pattern.
alter table public.calendars enable row level security;
alter table public.bookings enable row level security;

create policy calendars_tenant on public.calendars for all to authenticated
  using (app.is_agency() or account_id = app.current_account_id())
  with check (app.is_agency() or account_id = app.current_account_id());
create policy bookings_tenant on public.bookings for all to authenticated
  using (app.is_agency() or account_id = app.current_account_id())
  with check (app.is_agency() or account_id = app.current_account_id());

-- Column grants. Settings are client-editable (M4c precedent); identity is
-- not; bookings get NO client UPDATE grant at all — operator mutations go
-- through server actions, the public flow through service role.
revoke update on public.calendars from authenticated;
grant update (enabled, slot_duration_minutes, buffer_minutes, min_notice_hours,
              max_advance_days, open_hours, notify_emails)
  on public.calendars to authenticated;
revoke update on public.bookings from authenticated;
```

describe("booking accessors", () => {

```ts
const WEEKDAYS = ["sun", "mon", "tue", "wed", "thu", "fri", "sat"] as const;

export function partsInZone(instant: Date, timeZone: string) {
  const fmt = new Intl.DateTimeFormat("en-US", {
    timeZone, hourCycle: "h23",
    weekday: "short", year: "numeric", month: "numeric", day: "numeric",
    hour: "numeric", minute: "numeric",
  });
  const p: Record<string, string> = {};
  for (const part of fmt.formatToParts(instant)) p[part.type] = part.value;
  return {
    y: Number(p.year), m: Number(p.month), d: Number(p.day),
    hh: Number(p.hour), mi: Number(p.minute),
    weekday: p.weekday!.toLowerCase().slice(0, 3) as (typeof WEEKDAYS)[number],
  };
}

/** Wall time in `timeZone` → instant. Null when the wall time does not exist
 *  (the DST spring-forward gap): callers SKIP such slots rather than shifting
 *  them, because offering "2:30" on a day with no 2:30 books a lie. */
export function zonedTimeToUtc(y: number, m: number, d: number, hh: number, mi: number, timeZone: string): Date | null {
  let ts = Date.UTC(y, m - 1, d, hh, mi);
  for (let i = 0; i < 2; i++) {
    const p = partsInZone(new Date(ts), timeZone);
    ts += Date.UTC(y, m - 1, d, hh, mi) - Date.UTC(p.y, p.m - 1, p.d, p.hh, p.mi);
  }
  const check = partsInZone(new Date(ts), timeZone);
  if (check.y !== y || check.m !== m || check.d !== d || check.hh !== hh || check.mi !== mi) return null;
  return new Date(ts);
}
```

`computeSlots`: earliest offerable instant = `now + minNoticeHours` (inclusive — a slot exactly on the boundary is offered); horizon end = `now + maxAdvanceDays` days. Enumerate days by anchoring **noon in-zone** (noon dodges both DST edges) starting from `now`'s in-zone date, `maxAdvanceDays + 1` iterations. For each day, look up `openHours[weekday]`; for each `[from, to]` interval, parse `HH:MM`, step candidates by `slotDurationMinutes` from `from` while `candidateEnd <= to`; resolve each candidate through `zonedTimeToUtc` (skip nulls); drop candidates before the notice boundary or past the horizon; conflict test against each booked range `b`: `candStart < b.endsAt + buffer && b.startsAt < candEnd + buffer` (buffer on both sides — conservative and symmetric, documented in a comment). Return sorted.
