# The record's AI summary, PR 8a-2 (S-15 + F-020 slice, first release item 8, migration 0087): implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On a customer's record page, under the summary card's facts line, a short paragraph written by AI says where things stand with the customer and what is next, in the reader's language, marked "Generated by AI · 9:42 AM" with a ghost **Regenerate**. It is built only from team-visible facts (never message, email, chat or note bodies; never Owners-only files), cached per customer per language, rewritten when its inputs change or on Regenerate (once a minute per customer), and capped at 200 written summaries a day per account. Switched off or over budget, it is simply absent; past the cap it shows a plain note; a failure shows its own error with Retry. The facts line never moves and never fails with it. The agency's AI card on Settings gains "N of 200 customer summaries written today".

**Architecture:** One migration, **0087** (`record_summaries`): one cache table keyed `(account_id, contact_id, language)` with a same-account composite FK to `contacts` (`on delete cascade`), RLS SELECT for the account's members filtered through the reader's own `contacts` RLS (so a Technician reads only assigned customers' rows), no client write grant, and one `security definer` function `claim_record_summary` (service_role only) that hands out a 30-second lease and enforces the once-a-minute Regenerate. 0087 does NOT touch 0086: `ai_ledger_record` already counts `record_summary` / `ok` per account day (`0086_ai_gateway.sql:152`, `:163-167`) and `ai_gate_check` already returns `record_summaries_today` (`:124`). A new `@bis/db` module `record-summaries.ts` wraps the table and the RPC. In the web app: `lib/record/ai-summary-inputs.ts` builds a typed, bounded, redacted input object on the REQUEST client; `lib/record/ai-summary-prompt.ts` turns it into messages; `lib/record/ai-summary-view.ts` holds the response type, its parser, the label and the cap; `lib/record/ai-summary-service.ts` decides serve / claim / generate / save with injected dependencies; the route `app/api/accounts/[accountId]/contacts/[contactId]/ai-summary/route.ts` (GET, POST = Regenerate) proves the contact on the request client, then wires the service client into the gate, the claim, `aiComplete` and the save. A `"use client"` part inside the summary card fetches it after the page, with its own boundary.

**Tech Stack:** Postgres 17 (Supabase) migration; supabase-js 2.110.8; Next.js 16 App Router route handlers; React 19 client component; vitest 4 (`renderToStaticMarkup`, no DOM; `vi.mock`, `vi.stubEnv`); `node:crypto` sha256; the `@bis/db` suites on a local PG18 replica (plus a local PostgREST for `withTestAccount`) and CI `verify`; Playwright (bis-e2e-qa writes it, the orchestrator runs it) against `AI_PROVIDER=fake`.

## Deviations from the spec, and spec-vs-code mismatches (the source decided; evidence cited)

1. **0087 adds nothing to 0086.** Spec §4.6 says the cap uses `ai_ledger_record`'s counter: it already exists (`0086_ai_gateway.sql:152` `v_inc := case when p_feature = 'record_summary' and p_outcome = 'ok' then 1 else 0 end`; `:163-167` resets on a newer day) and `ai_gate_check` already returns it (`:124`), read by `aiGateCheck` (`packages/db/src/ai-gateway.ts:22-35`, `recordSummariesToday`). No ledger outcome is added, and the ledger's check constraint (`0086:42-43`) is untouched.
2. **The route checks the cap, not the gateway.** `aiComplete` refuses on the two switches and the budget only (`apps/web/src/lib/ai/gateway.ts:100-103`); it never reads `recordSummariesToday`. The route reads the gate itself first (`aiGateCheck` on the service client) and decides `none` / `capped` / proceed; `aiComplete` then reads the gate again for its own spend check. One extra RPC per open, and a capped or switched-off open writes **no ledger row** (it is not an attempted completion), so the Settings card's "AI was skipped N times" (0086's refusal rows) does not count record opens.
3. **Switched off or over budget hides even a fresh cached paragraph** (G6, I13: "the record summary becomes the facts line"); **past the cap a fresh cached paragraph is still served** (§4.6). A gate that cannot be read is `none` (fail closed, I9).
4. **Columns the spec does not list:** `lease_id uuid` (the lease's compare-and-set token: the winner's save and release match it, so a winner whose lease lapsed never overwrites a newer winner), `created_at`, coherence checks (`body`, `input_digest`, `model`, `generated_at` are all set or all null; `lease_id` and `generating_until` likewise), `body` 1–2000 characters (spec: ≤ 2000), `input_digest` exactly 64 lowercase hex, `model` 1–64 (0086's own cap).
5. **The claim function answers a status word and owns the once-a-minute Regenerate.** `claim_record_summary(...)` returns `{status: "won", lease_id}`, `{status: "busy"}` (a live lease), `{status: "fresh"}` (not forced and the stored digest equals the caller's) or `{status: "too_soon"}` (forced on an UNCHANGED digest within 60 s of the last such forced win; a forced claim on a changed digest behaves like an unforced one, wins, and does not stamp `last_forced_at`, plan fix I6). The 30 s lease and the 60 s cool-down are constants in the SQL (spec §4.5, §4.6). The row lock (`for update`) is the one serialisation point.
6. **Empty `search_path`** (`set search_path = ''`, every name schema-qualified), the house rule since 0085 and 8a-1's deviation 1; spec §3.3 wrote `public`.
7. **The RLS fence is 0085's exact shape:** `contact_id in (select c.id from public.contacts c)` as a restrictive policy (`0085_document_shares.sql:99-100`); the spec calls it "an exists on contacts".
8. **The builder's signature is `buildSummaryInputs(db, { accountId, contact, zone, now })`.** It takes the contact row the route already read through `getContact` (no second `contacts` read) and the account's zone (every date is local, §4.4). Spec: `(db, accountId, contactId, now)`.
9. **Bookings carry no calendar name.** `calendars` has no name column and there is one per account (`packages/db/src/booking.ts:1038-1039`). Each booking is its local start and its status.
10. **The no-bodies probe pins column lists instead of forbidding two tables.** Spec §4.3/§8.2 say the builder never calls `from("messages")` or `from("conversations")`, but the "last talked" fact the same section requires reads both (`contactFacts` → `newestConversationMessage`, `packages/db/src/record.ts:58-71`: `conversations.select("id")`, `messages.select("channel, created_at")`). The probe asserts the builder's reads are exactly the allowed set of tables, that those two reads select exactly `"id"` and `"channel, created_at"`, that `notes` and `concierge_conversations` are never read, and that no select names `body`, `subject`, `content` or `transcript`.
11. **Any failed builder read makes the answer `failed`** (no generation from partial inputs). `contactFacts` never throws (`record.ts:99-112`); a fact that answers `{ ok: false }` is treated as a failed read.
12. **The digest covers `{ v: SUMMARY_PROMPT_VERSION, inputs }`**, so a change to the prompt rewrites every cached paragraph on its next open.
13. **`ready` carries `stamp`**, the server-built label ("Generated by AI · 9:42 AM"), beside the spec's `text`, `generatedAt`, `language`. The client formats no date, and the QA pseudo-locale reaches the label.
14. **The label shows the date when the paragraph was not written today** ("Generated by AI · Oct 14, 9:42 AM"). Read with node 24 here (`Intl.DateTimeFormat`, America/Chicago): `9:42 AM`, `Oct 14, 9:42 AM`, `9:42 a.m.`, `14 oct, 9:42 a.m.`. The spec wrote "9:42 a. m."; the plan pins Intl's own output (Assumption A1 for CI's Node 22).
15. **The AI part mounts only when the facts line rendered.** When the summary card is in its error state (`page.tsx:211-213`, `failed(tr.text("record.summary.failed"))`), there is no AI part.
16. **The route guards the id with `isUuid` and lowercases it**, as `document-requests/route.ts:21-23` does. A route error after the contact proof answers HTTP 200 `{ state: "failed" }`, so the client has one failure path; a 404 is still a 404.

```ts
  // An OUTCOME test, as document-shares-schema.test.ts's. A first takes the row's lock with a plain

  // (inside the same transaction) and commit. With `for update` in the function, B waits at its own
  // `select … for update`, then reads A's lease and answers busy. Without it, B's plain select reads the
  // row as it was (no lease), B waits at its UPDATE instead, re-checks `s.id = v.id` after A commits, and
```

```sql
-- (docs/superpowers/specs/2026-10-18-ai-gateway-record-summary-design.md section 4.5;
--  docs/superpowers/plans/2026-10-18-ai-record-summary-pr8a2.md)

-- One row per customer per language: the paragraph the record page shows under its facts line, the
-- digest of the inputs it was written from (the app compares it on open: a different digest means the
-- paragraph is stale), and a 30-second lease so one reader writes while every other reader waits.
-- The app writes it through the service role only, after the route proved the customer on the
-- reader's own client. The client role reads a row exactly when it can read the customer (the
-- restrictive policy's subquery runs under contacts' own policies, 0068's Technician fence included)
-- and writes nothing. claim_record_summary (service_role only) creates the row if missing, locks it,
-- and answers busy (a live lease), fresh (not forced and the digest is unchanged), too_soon (forced,
-- the digest unchanged, within a minute of the last such forced claim) or won with a new lease_id the
-- save must match. A changed digest is never too_soon. The cool-down is per row, so per language.
-- The daily cap is NOT here: 0086's ai_ledger_record already counts successful record_summary rows
-- per account day, and ai_gate_check already returns the count. This migration does not touch 0086.

-- APPLY ORDER: CI project (ci-project-setup.yml: push-dry-run, then push), then production (MCP
-- apply_migration, once), then the parity check, then merge. Additive: the build before it reads
-- none of it. The build after it needs it (the record page's AI part fails to its error state

  contact_id uuid not null,

  model text constraint record_summaries_model_check check (char_length(model) between 1 and 64),
```

```ts
import type { SupabaseClient } from "@supabase/supabase-js";

/**
 * Item 8a-2 (spec 4.5; plan deviations 4, 5): the record page's AI paragraph, cached per customer per
 * language (0087). The READ runs on the reader's REQUEST client (0087's RLS decides: a Technician reads
 * only assigned customers' rows). The claim, the save and the release run on the SERVICE client, after
 * the route proved the customer on the request client. Nothing here takes or returns a prompt.
 */
export type SummaryLanguage = "en" | "es";
export type RecordSummaryKey = { accountId: string; contactId: string; language: SummaryLanguage };
export type RecordSummaryRow = { body: string | null; inputDigest: string | null; model: string | null; generatedAt: string | null };
export type RecordSummaryClaim = { status: "won"; leaseId: string } | { status: "busy" } | { status: "fresh" } | { status: "too_soon" };

const UUID = /^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/;

export async function getRecordSummary(db: SupabaseClient, k: RecordSummaryKey): Promise<RecordSummaryRow | null> {
  const { data, error } = await db.from("record_summaries").select("body, input_digest, model, generated_at")
    .eq("account_id", k.accountId).eq("contact_id", k.contactId).eq("language", k.language).maybeSingle();
  if (error) throw new Error(`getRecordSummary failed: ${error.message}`);
  if (!data) return null;
  const r = data as { body: string | null; input_digest: string | null; model: string | null; generated_at: string | null };
  return { body: r.body, inputDigest: r.input_digest, model: r.model, generatedAt: r.generated_at };
}

/** One claim (0087's claim_record_summary). THROWS on an error or an answer of any other shape. */
export async function claimRecordSummary(
  db: SupabaseClient, k: RecordSummaryKey & { digest: string; force: boolean },
): Promise<RecordSummaryClaim> {
  const { data, error } = await db.rpc("claim_record_summary", {
    p_account: k.accountId, p_contact: k.contactId, p_language: k.language, p_digest: k.digest, p_force: k.force,
  });
  if (error) throw new Error(`claimRecordSummary failed: ${error.message}`);
  const r = data as Record<string, unknown> | null;
  if (r && r.status === "won" && typeof r.lease_id === "string" && UUID.test(r.lease_id)) return { status: "won", leaseId: r.lease_id };
  if (r && (r.status === "busy" || r.status === "fresh" || r.status === "too_soon")) return { status: r.status };
  throw new Error("claimRecordSummary: unexpected answer");
}

/** The winner's write: only while its own lease still holds the row. False = another claim took it over. */
export async function saveRecordSummary(
  db: SupabaseClient, k: RecordSummaryKey & { leaseId: string; body: string; digest: string; model: string; generatedAt: string },
): Promise<boolean> {
  const { data, error } = await db.from("record_summaries")
    .update({ body: k.body, input_digest: k.digest, model: k.model, generated_at: k.generatedAt, generating_until: null, lease_id: null })
    .eq("account_id", k.accountId).eq("contact_id", k.contactId).eq("language", k.language).eq("lease_id", k.leaseId)
    .select("id");
  if (error) throw new Error(`saveRecordSummary failed: ${error.message}`);
  return (data ?? []).length === 1;
}

/** A failed generation lets the next reader claim at once instead of waiting out the lease. */
export async function releaseRecordSummaryLease(db: SupabaseClient, k: RecordSummaryKey & { leaseId: string }): Promise<void> {
  const { error } = await db.from("record_summaries").update({ generating_until: null, lease_id: null })
    .eq("account_id", k.accountId).eq("contact_id", k.contactId).eq("language", k.language).eq("lease_id", k.leaseId);
  if (error) throw new Error(`releaseRecordSummaryLease failed: ${error.message}`);
}
```

```ts
/**
 * The record summary's inputs (item 8a-2, spec 4.3, 4.4; plan deviations 8-12). Read on the REQUEST
 * client, so RLS (0068's Technician fence, 0077's Owners-only fence) decides as it does for the page; the

 * reader who can open the record builds the same inputs. NEVER a message, email, chat or note body: the
 * last-talked fact reads conversations.id and messages.channel/created_at only (record.ts:58-71). No phone,
 * email, address, custom field or tag; call summaries are redacted. Every list is capped, every text cut.
 * THROWS on any failed read: a summary is never written from partial inputs.
 */
export type SummaryContact = { id: string; first_name: string | null; language: string | null; created_at: string; source: string | null };
export type SummaryInputs = {
  who: { firstName: string | null; language: "en" | "es" | null; since: string; source: string | null };
  facts: { bookingsMade: number; lastTalked: { channel: "text" | "email" | "call" | "chat"; on: string } | null; openDeals: { count: number; amount: number | null } };
  bookings: { at: string; status: string }[];
  nextBooking: { at: string; status: string } | null;
  deals: { name: string; stage: string | null; amount: number }[];
  todos: { title: string; due: string | null }[];
  documents: { title: string; category: string }[];
  calls: { on: string; outcome: string; summary: string }[];
};
export const INPUT_LIMITS = { bookings: 5, deals: 10, todos: 10, documents: 10, calls: 5, title: 120, summary: 600, short: 60 } as const;

const cut = (s: string | null | undefined, n: number): string => (s ?? "").replace(/\s+/g, " ").trim().slice(0, n);
const cutOrNull = (s: string | null | undefined, n: number): string | null => cut(s, n) || null;

function parts(iso: string, zone: string) {
  const p = new Intl.DateTimeFormat("en-CA", { timeZone: zone, year: "numeric", month: "2-digit", day: "2-digit", hour: "2-digit", minute: "2-digit", hourCycle: "h23" })
    .formatToParts(new Date(iso));
  const get = (t: string) => p.find((x) => x.type === t)?.value ?? "";
  return { y: get("year"), m: get("month"), d: get("day"), h: get("hour"), min: get("minute") };
}
export const localDay = (iso: string, zone: string): string => { const x = parts(iso, zone); return `${x.y}-${x.m}-${x.d}`; };
export const localMinute = (iso: string, zone: string): string => { const x = parts(iso, zone); return `${x.y}-${x.m}-${x.d} ${x.h}:${x.min}`; };

/** Phone numbers and email addresses out of free text (I6). Seven or more digits is a number; an ISO date is not. */
export function redactContactDetails(text: string): string {
  return text
    .replace(/[^\s@<>()"]+@[^\s@<>()"]+\.[A-Za-z]{2,}/g, "[email]")
    .replace(/\+?\(?\d[\d\s().-]{5,}\d/g, (s) => (s.replace(/\D/g, "").length >= 7 && !/^\d{4}-\d{2}-\d{2}$/.test(s) ? "[number]" : s));
}

function must<T>(label: string, r: { data: T | null; error: { message: string } | null }): T {
  if (r.error) throw new Error(`summary inputs: ${label} read failed: ${r.error.message}`);
  return (r.data ?? []) as T;
}

export async function buildSummaryInputs(
  db: SupabaseClient, a: { accountId: string; contact: SummaryContact; zone: string; now: Date },
): Promise<SummaryInputs> {
  const { accountId, contact, zone } = a;
  const contactId = contact.id;
  const L = INPUT_LIMITS;
  const [facts, bookings, next, deals, todos, documents, calls] = await Promise.all([
    contactFacts(db, accountId, contactId),
    db.from("bookings").select("starts_at, status").eq("account_id", accountId).eq("contact_id", contactId)
      .order("starts_at", { ascending: false }).limit(L.bookings),
    db.from("bookings").select("starts_at, status").eq("account_id", accountId).eq("contact_id", contactId)
      .eq("status", "booked").gte("starts_at", a.now.toISOString()).order("starts_at", { ascending: true }).limit(1),
    db.from("opportunities").select("name, monetary_value, stage_id").eq("account_id", accountId).eq("contact_id", contactId)
      .eq("status", "open").order("created_at", { ascending: false }).limit(L.deals),
    db.from("tasks").select("title, due_at").eq("account_id", accountId).eq("contact_id", contactId)
      .is("completed_at", null).order("created_at", { ascending: false }).limit(L.todos),
    db.from("documents").select("title, category").eq("account_id", accountId).eq("contact_id", contactId)
      .is("deleted_at", null).eq("owners_only", false).order("created_at", { ascending: false }).limit(L.documents),
    listContactCalls(db, accountId, contactId, L.calls, { excludeSpam: true }),

  if (stageIds.length > 0) {

      await db.from("pipeline_stages").select("id, name").eq("account_id", accountId).in("id", stageIds));
    for (const row of s) stages.set(row.id, row.name);

    nextBooking: nextRows[0] ? booking(nextRows[0]) : null,
    deals: dealRows.map((d) => ({ name: cut(redactContactDetails(d.name), L.title), stage: cutOrNull(stages.get(d.stage_id), L.short), amount: Number(d.monetary_value) })),
    todos: must<{ title: string; due_at: string | null }[]>("tasks", todos).map((t) => ({ title: cut(redactContactDetails(t.title), L.title), due: t.due_at ? localDay(t.due_at, zone) : null })),
    documents: must<{ title: string; category: string }[]>("documents", documents).map((d) => ({ title: cut(redactContactDetails(d.title), L.title), category: d.category })),
    calls: calls.map((k) => ({ on: localDay(k.started_at, zone), outcome: k.outcome, summary: cut(redactContactDetails(k.summary ?? ""), L.summary) })),
  };
}

export function hasSomethingToSay(i: SummaryInputs): boolean {
  return i.bookings.length > 0 || i.nextBooking !== null || i.deals.length > 0 || i.todos.length > 0
    || i.documents.length > 0 || i.calls.some((k) => k.summary !== "");
}

/** Keys sorted at every depth; arrays keep their order. */
export function canonicalJson(v: unknown): string {
  if (Array.isArray(v)) return `[${v.map(canonicalJson).join(",")}]`;
  if (v !== null && typeof v === "object") {
    return `{${Object.keys(v as Record<string, unknown>).sort().map((k) => `${JSON.stringify(k)}:${canonicalJson((v as Record<string, unknown>)[k])}`).join(",")}}`;
  }
  return JSON.stringify(v);
}

export function inputDigest(i: SummaryInputs, version: number): string {
  return createHash("sha256").update(canonicalJson({ v: version, inputs: i })).digest("hex");
}
```

```ts
import type { AiMessage, AiResult } from "@/lib/ai/gateway";
import { aiSafeError } from "@/lib/ai/log";
import { inputDigest, type SummaryInputs } from "./ai-summary-inputs";
import { cleanSummary, summaryMessages, SUMMARY_PROMPT_VERSION } from "./ai-summary-prompt";
import { RECORD_SUMMARY_DAILY_CAP, type AiSummaryResponse } from "./ai-summary-view";

/**
 * Item 8a-2 (spec 4.2, 4.4-4.6; plan deviations 2, 3, 21, 22): what one open (or one Regenerate) of the
 * record summary answers. NEVER throws. The gate first: switched off or over budget is none, even with a
 * fresh cached paragraph (G6); an unreadable gate is none (I9). Then the cache (read under the reader's RLS):
 * an unchanged digest is served. Past the day's cap a fresh paragraph is served and anything else is capped.
 * Then one claim: one reader wins the lease and writes; the others answer generating. The gateway reads
 * the gate again and writes the ledger row; a refusal there releases the lease. Logs ids and state words
 * only, never the inputs or the answer.
 */
export type SummaryDeps = {
  gate(): Promise<AiGate>;
  cached(): Promise<RecordSummaryRow | null>;
  claim(digest: string, force: boolean): Promise<RecordSummaryClaim>;
  complete(messages: AiMessage[]): Promise<AiResult>;
  save(s: { leaseId: string; body: string; digest: string; generatedAt: string }): Promise<boolean>;
  release(leaseId: string): Promise<void>;
  now(): Date;
  log(line: string): void;
};
/** Configuration, not a fault (orchestrator ruling M7): nothing is shown. Everything else non-ok is "failed". */
const QUIET = new Set(["global_off", "account_off", "over_budget", "no_key", "unknown_model"]);

export async function serveRecordSummary(
  deps: SummaryDeps, a: { inputs: SummaryInputs; language: "en" | "es"; force: boolean; stamp: (iso: string) => string },
): Promise<AiSummaryResponse> {
  const ready = (text: string, generatedAt: string): AiSummaryResponse => ({ state: "ready", text, generatedAt, language: a.language, stamp: a.stamp(generatedAt) });
  const servable = (row: RecordSummaryRow | null) => (row?.body && row.generatedAt ? row as { body: string; generatedAt: string } : null);
  let gate: AiGate;
  try {
    gate = await deps.gate();
  } catch (e) {
    deps.log(`gate unreadable, no summary: ${aiSafeError(e)}`);
    return { state: "none" };
  }
  if (!gate.globalEnabled || !gate.accountEnabled || gate.monthSpendMicroUsd >= gate.budgetMicroUsd) return { state: "none" };
  let lease: string | null = null;
  try {
    const digest = inputDigest(a.inputs, SUMMARY_PROMPT_VERSION);
    const row = await deps.cached();
    const have = servable(row);
    const fresh = have !== null && row!.inputDigest === digest;
    if (fresh && !a.force) return ready(have.body, have.generatedAt);
    if (gate.recordSummariesToday >= RECORD_SUMMARY_DAILY_CAP) return fresh ? ready(have!.body, have!.generatedAt) : { state: "capped" };
    const claim = await deps.claim(digest, a.force);
    if (claim.status === "busy") return { state: "generating" };
    if (claim.status === "fresh" || claim.status === "too_soon") {
      const now = servable(await deps.cached()) ?? have;
      return now ? ready(now.body, now.generatedAt) : { state: "generating" };
    }
    lease = claim.leaseId;
    const answer = await deps.complete(summaryMessages(a.inputs, a.language));
    const body = answer.ok ? cleanSummary(answer.text) : null;
    if (!answer.ok || body === null) {
      const held = lease;
      lease = null;
      const quiet = !answer.ok && QUIET.has(answer.reason);
      // A release that throws never turns a quiet refusal into an error (ruling M11): the lease lapses in 30 s.
      try {
        await deps.release(held);
      } catch (e) {
        deps.log(`lease release failed: ${aiSafeError(e)}`);
      }
      return { state: quiet ? "none" : "failed" };
    }
    const generatedAt = deps.now().toISOString();
    const saved = await deps.save({ leaseId: lease, body, digest, generatedAt });
    lease = null;
    if (!saved) deps.log("lease lapsed before the save; showing this answer, not storing it");
    return ready(body, generatedAt);
  } catch (e) {
    deps.log(`summary failed: ${aiSafeError(e)}`);
    if (lease) await deps.release(lease).catch(() => {});
    return { state: "failed" };
  }
}
```

```ts
 * assigned customer (0068). The inputs and the cache read run on the request client too (RLS decides). Only

async function answer(req: Request, { params }: Params, force: boolean): Promise<NextResponse> {
  const { accountId, contactId: raw } = await params;
  const access = await apiAccountAccess(accountId);
  // Both ids are checked (plan fix M5): an agency session passes apiAccountAccess for ANY accountId string
  // (lib/auth.ts:184), so a malformed one would otherwise reach the queries.
  if (!access || !isUuid(accountId) || !isUuid(raw)) return NextResponse.json({}, { status: 404 });
  const contactId = raw.toLowerCase();
  const db = await dbForRequest(); // RLS-scoped: NEVER serviceDb before getContact proved the customer
  const failed = (where: string, e: unknown) => {
    console.error(`record summary: account ${accountId} contact ${contactId}: ${where}: ${loggableError(e)}`);
    return NextResponse.json({ state: "failed" } satisfies AiSummaryResponse);
  };
  let contact: SummaryContact | null;
  try {
    contact = (await getContact(db, accountId, contactId)) as SummaryContact | null;
  } catch (e) {
    return failed("contact read", e);
  }
  if (!contact) return NextResponse.json({}, { status: 404 });

  const localeParam = new URL(req.url).searchParams.get("locale") ?? undefined;
  const now = new Date();
  try {
    const [prefs, account] = await Promise.all([
      getPersonPrefs(),
      db.from("accounts").select("timezone, language").eq("id", accountId).maybeSingle(),
    ]);
    if (account.error) console.error(`record summary: account ${accountId} timezone and language read failed: ${account.error.message}`);
    const accountRow = account.data as { timezone: string; language?: Locale | null } | null;
    const zone = (await renderZone(accountRow?.timezone)).zone;
    // A named variable, not an inline literal: request-locale-callers.test.ts scans each call's braces.
    const accountLanguage = { language: accountRow?.language ?? null };
    const locale = requestLocale({ account: accountLanguage, isOperator: access.isAgency, userLanguage: prefs.language }, { locale: localeParam });
    const tr = makeTr(locale, requestPseudoMode({ locale: localeParam }));

    const inputs = await buildSummaryInputs(db, { accountId, contact, zone, now });
    if (!hasSomethingToSay(inputs)) return NextResponse.json({ state: "none" } satisfies AiSummaryResponse);

    const svc = serviceDb();
    const key = { accountId, contactId, language: locale };
    const body = await serveRecordSummary({
      gate: () => aiGateCheck(svc, { accountId, ...periodKeys(now, zone), signal: AbortSignal.timeout(GATE_TIMEOUT_MS) }),
      cached: () => getRecordSummary(db, key),
      claim: (digest, f) => claimRecordSummary(svc, { ...key, digest, force: f }),
      complete: (messages) => aiComplete(svc, {
        accountId, feature: "record_summary", model: SUMMARY_MODEL, messages, maxTokens: SUMMARY_MAX_TOKENS,
        timeoutMs: SUMMARY_TIMEOUT_MS, timezone: zone, language: locale, ref: `contact ${contactId}`,
      }),
      save: (s) => saveRecordSummary(svc, { ...key, ...s, model: SUMMARY_MODEL }),
      release: (leaseId) => releaseRecordSummaryLease(svc, { ...key, leaseId }),
      now: () => new Date(),
      log: (line) => console.error(`record summary: account ${accountId} contact ${contactId}: ${line}`),
    }, { inputs, language: locale, force, stamp: (iso) => aiSummaryStamp(iso, { zone, now: new Date(), tr }) });
    return NextResponse.json(body);
  } catch (e) {
    return failed("inputs", e);
  }
}

export function GET(req: Request, ctx: Params) { return answer(req, ctx, false); }
export function POST(req: Request, ctx: Params) { return answer(req, ctx, true); }
```

```ts
import { parseAiSummary, type AiSummaryResponse } from "@/lib/record/ai-summary-view";

/** One ask, then (I4) a re-ask every 2 s while another reader writes, at most 15 times. Never throws. */
export const POLL_EVERY_MS = 2_000;
export const POLL_LIMIT = 15;
type Fetch = (url: string, init?: RequestInit) => Promise<Response>;

export async function loadAiSummary(
  url: string, o: { force: boolean; fetchImpl?: Fetch; wait?: (ms: number) => Promise<void>; signal?: AbortSignal },
): Promise<AiSummaryResponse> {
  const f: Fetch = o.fetchImpl ?? ((u, init) => fetch(u, init));
  const wait = o.wait ?? ((ms: number) => new Promise<void>((r) => setTimeout(r, ms)));
  const ask = async (method: "GET" | "POST"): Promise<AiSummaryResponse> => {
    try {
      const res = await f(url, { method, cache: "no-store", signal: o.signal });
      if (!res.ok) return { state: "failed" };
      return parseAiSummary(await res.json());
    } catch {
      return { state: "failed" };
    }
  };
  let r = await ask(o.force ? "POST" : "GET");
  for (let i = 0; i < POLL_LIMIT && r.state === "generating"; i++) {
    await wait(POLL_EVERY_MS);
    if (o.signal?.aborted) return r;
    r = await ask("GET");
  }
  return r.state === "generating" ? { state: "failed" } : r;
}
```
